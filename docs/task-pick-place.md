# 태스크 정의 — pick-and-place

TY-8 스파이크 결과. 이 문서의 숫자는 세 곳에서 그대로 쓰인다.

| 쓰는 곳 | 무엇을 가져가나 |
|---|---|
| TY-17 씬 리셋 서비스 | 물체 스폰 분포 · 목표 존 위치 · seed 지터 범위 |
| TY-44 평가 조건표 · TY-106 성공 판정 함수 | 성공 정의 · 실패 모드 · 조건표 축 |
| TY-111 RL 보상 함수 | 성공 판정 함수 + shaping 항 |

나중에 바꾸면 세 곳이 동시에 틀어진다. 그래서 **확정한 것**과 **측정 후 채울 것**을 아래에서 분리했다.

---

## 1. 로봇과 좌표계

SO-101 팔로워는 **팔 관절 5개 + 그리퍼 1개**다(`shoulder_pan`, `shoulder_lift`, `elbow_flex`, `wrist_flex`, `wrist_roll`, `gripper`).

5-DoF라서 임의의 6D pose에 도달할 수 없다. 따라서 태스크를 **top-down 파지**로 고정한다. 그리퍼는 항상 아래를 보고, `wrist_roll`로 yaw만 맞춘다. 제어해야 하는 자유도가 (x, y, z, yaw)로 줄어들어 IK가 단순해지고(TY-20), 텔레오퍼레이션 매핑도 게임패드 스틱 2개 + 트리거로 덮인다.

좌표계는 로봇 베이스 프레임을 쓴다. 원점은 베이스 하단 중심, **+x 정면 · +y 왼쪽 · z 위**, 단위는 미터와 라디안. 테이블 상판은 `z = 0`.

## 2. 물체와 목표 존

| 항목 | 값 | 근거 |
|---|---|---|
| 기본 물체 | 한 변 25mm 정육면체, 질량 20g | STS3215 그리퍼가 안정적으로 무는 크기. 큐브는 top-down 파지에서 yaw만 맞추면 되어 실패 원인이 분리된다 |
| 추가 물체 (v1) | 지름 25mm · 길이 60mm 원통(눕힘) | 파지 축이 하나로 제한되어 yaw 민감도를 따로 측정할 수 있다 |
| 목표 존 | 80 × 80mm 사각, 고정 위치, 색상 패치로 표시 | 물체 25mm 대비 3배 — 정밀도보다 성공/실패 판정의 안정성을 우선 |
| 테이블 | 400 × 300mm 작업 영역 | 웹캠 탑뷰 1대로 전체가 들어오는 크기 |

목표 존은 v0~v4 내내 **고정**한다. 물체 초기 위치만 바꾼다. 목표까지 움직이면 조건 조합이 곱으로 늘어나 평가 시간이 감당되지 않고, 일반화 축이 둘로 섞여 원인 분석이 어려워진다. 목표 존 이동은 v5 멀티스텝에서 다룬다.

## 3. 성공 판정 (확정)

성공은 세 조건의 논리곱이다.

```
success = placed AND settled AND intact
```

| 조건 | 정의 |
|---|---|
| `placed` | 물체 중심의 (x, y)가 목표 사각형 내부이고, 중심 z ≤ 0.02 m (들고 있는 게 아니라 놓여 있음) |
| `settled` | 물체 선속도 크기 < 0.02 m/s **이고** 그리퍼-물체 접촉이 없는 상태가 연속 0.5초 유지 |
| `intact` | 에피소드 중 물체가 테이블 밖으로 떨어지지 않음 |

에피소드 타임아웃은 **20초**(50Hz 기준 1000 스텝). `settled`에 0.5초 유지 조건을 넣은 이유는, 존 경계에 걸쳐 놓고 굴러 나가는 케이스를 성공으로 세지 않기 위해서다.

판정 함수는 ROS 2 · MuJoCo 의존이 없는 순수 함수로 만든다(TY-106). 시뮬 평가 · 실물 평가 · RL 보상이 같은 코드를 쓰는 것이 목적이다.

```python
def check_success(s: TaskState) -> tuple[bool, str]:
    """(성공 여부, 실패 모드 코드). s는 프레임 하나에 대한 상태 스냅샷."""
```

`TaskState`에 담기는 것: 물체 pose · 선속도, 그리퍼 접촉 플래그, 목표 존 사각형, 경과 시간, 테이블 이탈 플래그, 최고 도달 높이. 실물에서는 물체 pose를 탑뷰 카메라 + AprilTag로 추정해 채운다(v3, TY-96에서 캘리브레이션).

## 4. 실패 모드 분류 (확정)

TY-90 태깅과 v3·v4 gap 분석이 이 코드를 쓴다.

| 코드 | 정의 | 무엇을 의심하나 |
|---|---|---|
| `grasp_miss` | 물체가 한 번도 50mm 이상 들리지 않음 | 파지 위치 추정, 그리퍼 폭·타이밍 |
| `drop` | 들렸다가 목표 도달 전에 놓침 | 파지 안정성, 이동 중 가속 |
| `misplace` | 놓았으나 존 밖 | 목표 위치 인식, 누적 오차 |
| `unsettled` | 존 안이지만 0.5초 안정 실패 | 놓는 높이, 릴리즈 속도 |
| `timeout` | 20초 초과 | 정책 정지·배회, 추론 지연 |
| `unsafe` | 관절 한계 위반 또는 테이블 충돌로 중단 | 안전 제한, 액션 스케일 |
| `out_of_bounds` | 물체가 테이블 밖으로 떨어짐 | 과도한 힘, 밀어내기 |

## 5. 관측과 액션 (계약 초안 → TY-10에서 확정)

| | 내용 | 주기 |
|---|---|---|
| 카메라 | 탑뷰 · 손목 각 RGB 320×240 | 30Hz |
| 관절 상태 | 위치 6 + 속도 6 | 50Hz |
| 액션 | 관절 위치 목표 6개(그리퍼 포함) | 50Hz |
| action chunk | horizon 20 (= 0.4초) | — |

해상도를 320×240으로 잡은 것은 8GB VRAM에서 ACT 학습 배치를 확보하기 위해서다. 최종 확정은 TY-39 학습 시 메모리 측정 후.

v4 RL의 상태 관측은 비전을 뺀다: 관절 위치·속도 12 + 물체 pose 7 + 목표 존 중심 2. 비전은 정책 본체(ACT)가 담당하고, residual은 기하만 본다.

## 6. 평가 조건표 (축 확정, 범위는 측정 후)

| 축 | 값 |
|---|---|
| 물체 초기 위치 | 도달 가능 영역 내 격자. **학습 분포 A** = 안쪽 셀, **held-out B** = 가장자리 셀과 A 셀 사이 지점 |
| 물체 yaw | 0° · 30° · 60° (큐브는 90° 주기라 이 셋으로 전 범위를 덮는다) |
| 물체 종류 | 큐브(기본) / 원통(v1 추가) |
| seed | 5개 — 위치 ±3mm · yaw ±3° 지터, 초기 관절 자세 지터 |

- **전체 조건표**: 격자 셀 × yaw 3 × seed 5. 격자 12셀이면 180 에피소드, 20초 타임아웃 기준 최대 1시간.
- **축약 조건표**(TY-89 회귀 감지용): 격자 4셀 × yaw 1 × seed 3 = 12 에피소드.

### 격자 범위를 정하는 절차 (TY-13에서 실행)

숫자를 지금 찍지 않고 측정으로 정한다.

1. 테이블 작업 영역을 20mm 간격 격자로 나눈다.
2. 각 셀 중심에 대해 top-down 파지 자세(그리퍼 수직, z = 물체 높이 기준)로 IK를 푼다.
3. 해가 있고 관절 한계에서 10% 이상 여유가 있는 셀만 후보로 남긴다.
4. 후보 영역 경계에서 10mm 안쪽으로 줄인 뒤, 학습 분포 A(안쪽 60%)와 held-out B(나머지)로 나눈다.
5. 결과 격자를 `config/task/pick_place.yaml`에 커밋한다. 이후 모든 평가가 이 파일을 읽는다.

## 7. 보상 (v4, TY-111)

성공 판정 함수를 그대로 쓰고 shaping을 얹는다.

```
r = 10.0 · success
  − 0.1 · (파지 전: |ee − object|,  파지 후: |object − target|)
  − 1e-3 · |jerk|
  − 0.1 · (관절 한계 위반량)
  − 0.01                          # 스텝 페널티 (빨리 끝내도록)
```

파지 전/후 전환은 그리퍼 접촉 + 물체 높이 50mm로 판정한다. 실패 모드 코드를 학습 로그에 같이 남겨, 보상이 어느 실패를 줄이고 있는지 추적한다.

## 8. MJX 호환 제약 (TY-105)

v4에서 GPU 병렬로 옮길 수 있게 씬을 만들 때부터 지킨다.

- 충돌 geom은 primitive(box · sphere · capsule)만. 메시는 시각 전용으로 둔다.
- 그리퍼 패드와 물체는 box–box 접촉으로, 마찰은 `pair`로 명시한다.
- equality constraint와 tendon은 쓰지 않는다.
- CI에 `mjx.put_model(model)` 스모크 테스트를 넣어 회귀를 막는다.

## 9. 데이터 수집 규격 (E3)

- v0 시연 30~50개. 물체 초기 위치는 **학습 분포 A에서만** 샘플한다(held-out B는 평가 전용).
- 시연 1회 = 에피소드 1개. 실패한 시연은 `discard` 서비스로 버리고 기록에 남기지 않는다.
- 에피소드 메타데이터에 태스크 config 해시를 넣어, 조건표가 바뀐 뒤 수집된 데이터를 구분할 수 있게 한다.

## 10. 확정 / 보류

**확정** — top-down 파지, 25mm 큐브, 80mm 목표 존, 고정 목표, 성공 판정 3조건, 실패 모드 7종, 20초 타임아웃, 조건표 축, 보상 구조, MJX 제약.

**보류(측정 후 채움)** — 격자 범위와 셀 수(TY-13), 카메라 포즈와 최종 해상도(TY-15 · TY-39), 실물 물체 pose 추정 방식의 정밀도(TY-96).
